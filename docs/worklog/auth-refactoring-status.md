## 현재 상황

이 작업공간에는 두 개의 Git 저장소가 있습니다.

- 루트 저장소 `online-sequencer`: 온라인 시퀀서 클라이언트
- 중첩 저장소 `jace-s`: 온라인 시퀀서 서버

관리자 인증·인가 구현은 서버와 클라이언트 양쪽에 반영되어 있습니다. 서버에서는 관리자 세션, 관리자 룸 API, 호스트 토큰, WebSocket 호스트 인증을 구현했고, 클라이언트에서는 로그인·세션·로그아웃·관리자 룸 관리·호스트 토큰 전달을 반영했습니다.

인증 재사용을 고려하여 서버의 관리자 인증 핵심 로직은 Next.js 요청·응답 처리와 분리했습니다.

- 프레임워크 비종속 인증 핵심: `jace-s/app/utils/auth/adminAuthCore.ts`
- Next.js 요청·쿠키 어댑터: `jace-s/app/utils/adminAuth.ts`
- 룸 기능과 호스트 토큰 정책: `jace-s` 앱 전용으로 유지

## 현재 동결한 이유

온라인 시퀀서 클라이언트 리팩토링은 현재 루트 저장소의 `stash@{0}`에 보관되어 있습니다.

stash 메시지:

```text
wip: online sequencer auth integration
```

클라이언트 변경을 동결한 이유는 다음과 같습니다.

1. 서버 인증 API 계약을 먼저 별도 커밋·푸시하고 실제 환경에서 검증해야 합니다.
2. 서버 변경과 클라이언트 리팩토링을 같은 작업 단위로 섞지 않기 위해서입니다.
3. 실제 로그인, 쿠키, CSRF, 관리자 룸 삭제, 호스트 토큰 흐름이 배포 환경에서도 동작하는지 확인한 뒤 클라이언트 리팩토링을 재개하기 위해서입니다.
4. 기존 루트 사용자 변경사항인 `vite.config.ts`와 기존 문서를 보호하기 위해서입니다.

동결은 구현을 폐기한 것이 아닙니다. 기존 클라이언트 변경은 stash에 보존되어 있으며, 서버 계약 검증 후 복원하여 계속 작업합니다.

## 서버 작업 상태

서버 저장소 `jace-s`는 `dev` 브랜치로 전환되어 있습니다. 인증·인가 변경사항은 아직 커밋하거나 원격에 push하지 않았습니다.

현재 서버에서 완료된 내용:

- 관리자 로그인·세션 확인·로그아웃
- 관리자 룸 목록·상세 조회·강제 삭제
- 관리자 세션, CSRF, 로그인 rate limit
- 일반 호스트 요청의 Bearer 호스트 토큰 검증
- WebSocket 호스트 등록 시 호스트 토큰 검증
- 기존 `verify-password` 경로의 deprecated 호환 처리
- 프레임워크 비종속 인증 핵심 분리
- 비밀번호 pepper의 안정적인 환경변수 사용
- cross-site 관리자 삭제 요청의 CSRF 검증

현재 운영 전제:

- 단일 서버 인스턴스
- 세션·rate limit·룸은 메모리 저장
- 서버 재시작 시 세션과 룸이 사라지는 것을 허용
- Redis, DB 기반 세션 저장소는 현재 범위에 포함하지 않음
- `PEPPER`는 재시작 후에도 동일한 서버 환경변수로 유지

## 검증 완료

다음 검증은 서버 저장소에서 통과했습니다.

- `npm run test:security`
- `npm run type-check`
- `npx eslint app scripts server.ts`
- `npm run build`
- `git diff --check`

자동 검증은 완료되었지만 실제 배포 환경에서의 브라우저·API 통합 테스트는 아직 수행하지 않았습니다.

## 다음 작업 순서

1. 서버 최종 diff를 검토합니다.
2. 커밋 메시지를 확정한 뒤 `jace-s`의 `dev` 브랜치에 서버 변경만 커밋합니다.
3. 서버 원격 저장소에 push합니다.
4. 실제 서버와 클라이언트를 올려 관리자 인증·룸 관리·호스트 권한 흐름을 테스트합니다.
5. 테스트가 끝나면 루트 저장소에서 `git stash apply 'stash@{0}'`로 클라이언트 작업을 복원합니다.
6. 온라인 시퀀서 클라이언트 리팩토링을 계속하고, 완료 후 루트 저장소에서 별도로 커밋합니다.

## 삭제·정리 주의사항

- 서버 push와 실제 배포 확인 전에는 로컬 `jace-s` 폴더를 삭제하지 않습니다.
- 루트 저장소에서 `git add jace-s`를 실행하지 않습니다. 서버는 별도 Git 저장소입니다.
- 루트의 기존 `vite.config.ts`와 문서는 사용자 변경사항이므로 임의로 되돌리지 않습니다.
- 비밀번호, pepper, 세션 ID, 호스트 토큰은 이 문서나 Git에 기록하지 않습니다.
